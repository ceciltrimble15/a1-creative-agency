# A/1 Creative: outcome-led build and review

This is Cecil Trimble's working standard for this repository. Read it before changing the website or designing a client workflow.

## Business first
- State the customer's problem, desired outcome, source of facts and acceptance checks before building. Reuse approved assets and existing systems.
- A/1 Creative builds the business system behind the brand. Preserve Business Transformation / Development / Growth Systems, Cecil's voice, the original logo and agreed offers.
- Distinguish proposed, implemented, tested, live and measured. Never invent results, stock, prices, integrations or compliance approval.
- Earth's Clean & Pure is a partner-led venture in Cecil's strategy, not merely a client engagement. Cecil leads sales, marketing, media and growth strategy; Jymii leads sourcing, product and production. A1 Creative's service role remains inside that partnership. Do not invent legal ownership percentages, accepted fees or profit splits. The multi-channel/live-commerce/import expansion is a six-month roadmap, not a claim of a launch today.

## Design for scanning
- The first screen must make the service, intended buyer and next step easy to identify.
- Use meaningful headings, short sentences, real visuals and one primary action per section. Lead with the customer's outcome.
- Keep key price, scope, status and buying details visible. Put optional depth on linked pages or accessible disclosures; never hide material conditions.
- Check the page by reading headings alone. Then inspect the actual mobile and desktop render. Do not certify visual quality from source code alone.
- Preserve accessible contrast, keyboard controls, reduced motion and responsive layouts. Motion must not delay the offer or CTA.

## Bounded build / review / fix loop
1. Freeze a short brief: goal, approved references, fixed facts, scope, checks and execution budget. New ideas go into the next version unless they correct a defect.
2. Inspect the current implementation; build the scoped change.
3. Run relevant functional checks and `npm run review:website -- --base-url=http://127.0.0.1:4173 --output-dir=artifacts/website-review`. Start a local server first. See docs/build-review-standard.md.
4. Inspect screenshots and the generated review report. A second role/agent must compare against the brief and real evidence, not merely agree with the builder. A single assistant can perform both roles sequentially.
5. Fix routine failures and rerun affected checks without asking Cecil about each correction. Default maximum: three correction rounds within the agreed budget; stop early on success. Escalate missing access, missing facts, repeated failures or material scope decisions as one bundled report.
6. Return the reviewed preview, changed behavior, checks, evidence and remaining blockers. Do not label an untested check as passed.

This is a supervised execution standard, not an installed autonomous background agent. The automated review command tests selected browser properties; it cannot judge the entire design or prove real lead delivery. No paid AI provider or new autonomous sending authority is introduced.

## Boundaries
- Preserve working forms, consent language, prices and account ownership unless the user authorizes a change.
- Publishing, messages, calls and spending follow existing user authorization. Use simulations for checks where a real action is not authorized.
- Do not infer a prospect's missed-call problem from its public website. Confirm operations with the owner and authorized live tests.
- Keep client recipes and customer data private. Keep A/1 Suppliers nonprofit work and TBF accounting separate.
- Production release remains subject to unresolved integration and release checks. Report blockers accurately; do not bypass them.
